The terminal event

The chain did not crash — no traceback, no CUDA OOM, no timeout. Job 15842429 exited 1 by design. The collector stopped because two commit targets failed the private teacher-target audit, and the zero-quarantine gate is cumulative and irreversible.

How close is it, really?

Only one unexecuted batch introduces new physical roots; the other three are additional replicas of roots already in the pool. Replicas still help — the floors count distinct roots bearing a row in that stratum, so a second trajectory can newly qualify an existing root — but the two effects should be reported separately.

Scaling the raw stratum labels linearly from 151 to 477 episodes (×3.16) gives roughly 9–10 labels per stratum against a floor of 10 distinct roots, where roots ≤ rows. That lands close enough to the boundary that neither "it will obviously fill" nor "it obviously cannot" is defensible from current data — which is exactly why an analysis-only complete-schedule run is worth building rather than assuming an outcome.

State-class plumbing defect

REAL · INDEPENDENT

159 rows reach state_class = invalid_precondition_recovery through a catch-all branch, not because anything is invalid. Every disposition source is empty, so the classifier falls through:

This did not cause the run to stop, and it does not skew the replay mixture — all three relevant class weights are 0.10. It does corrupt state-class audits, class-conditioned reporting, deterministic selector behaviour, and potentially bucket allocation.

Fix it from policy-visible verification evidence rather than by exposing private disposition, sharing one observable helper across expert commit/rollback reconstruction, state-class assignment, and rank-one target proof.

Decision

Do not start aggregate ingestion, Round-1 SFT, or DAgger iteration 2. Do not add counterfactual rows, lower the capacity target, or weaken the root floors. The run stopped too early to justify any methodological change.

Next-step sequence

  1. Preserve the failed bundle immutable. It is scientifically useful precisely because it records the exact censored checkpoint.
  2. Resolve the two quarantined commits forensically — genuine wrong-target commit, or legitimate refinement? Add both physical roots as regression fixtures. Do not weaken the zero-quarantine gate until this is answered.
  3. Fix state-class semantics from policy-visible evidence, with a regression test on the 159-row pattern.
  4. Add an analysis-only complete-schedule mode — same β, same seeds, same 477 episodes, continuing past quarantine for analysis only; every output training-ineligible, never accepted by aggregate ingestion.
  5. Regenerate hash-bound artifacts and rerun the strict β=0.25 protocol with β, row target, aggregate target 1630, root floors, and zero-quarantine all unchanged.

Monitoring

Orchestration should distinguish infrastructure failure (crash, OOM, timeout) from strict collection NO-GO (valid failure bundle, expected exit 1, production outputs absent) from GO (exit 0, manifest present). It should parse failure_evidence.json and report failed gate names — not call a job healthy because no traceback appeared.
