## 标准集没有明显收益的原因

冻结 R2、iteration 0、iteration 1 均为 159/160；错误提交分别为 23/20/23，无效动作 39/35/33。这是一次运行的配对描述，不能仅凭这些总数宣称统计显著改善或退化。

1. **成功率余量只有 1/160（0.625 个百分点）。** 488 次采样的审计成功全部为真；10/61、6/61 个组有奖励差异，主要来自成本、无效动作和错误路径，而不是采到了从失败到成功的新解。成功本身还包含有界/解释性转交，必须另外报告严格解决率。
2. **行为太确定。** 记录称 95% 的采样步骤所有被选 token 的概率至少为 0.99。该统计是被采样 token 的概率，不是完整分布的熵；应同时看语义动作、第一次修正目标和完整轨迹的多样性，不能把 JSON 格式变化当探索。
3. **组内标准差归一化抹去了跨组差异的绝对大小。** 当前 `advantages.py` 正确计算
   `A_i = (R_i - mean(R))/(std(R)+1e-6)`，常数失败组与常数成功组都为零。一组奖励 `[.8,.8,.8,.78]` 与 `[1,1,1,0]` 的优势形状几乎相同：前三个约 `+.577`，最后约 `-1.732`。省一次调用可以拥有接近成功/失败分歧的标准化幅度。
4. **更新的“ratio=1”条件在第二个 optimizer step 不成立。** `update.py` 打乱并分成两个 chunk；第一个 chunk 的 `optimizer.step()` 后模型已改变，第二个仍用 `-A*log pi_current`，没有行为概率比或 PPO clipping。每条样本只用一次并不能保证第二个 step 仍 on-policy。这是明确的估计问题，但现有日志不能证明它导致了尖峰或全部性能停滞。
5. **历史配对缺失偏向异常输出。** iteration 0 的 16/244 条轨迹未配对，恰好可能丢失应被惩罚的输出；`e622689` 已在 iteration 1 前修好，不能再把它列为待实现项。top-k/top-p、温度一致性、起始 adapter KL reference 和断点续跑也已修复。

两轮一共只有 4 次 optimizer step；这些结果足以说明本次设置缺少诊断收益，尚不足以证明 RL 本身无效。

在固定 K=4、相同样本与缩放方式下，RLOO 的中心化优势恰是 GRPO 中心化优势的 `4/3`。因此单纯把 `grpo/group` 改成 `rloo/group` 不是优先实验；先比较 `grpo/group` 与 `grpo/none`，才能直接检验小成本差异是否被过度放大。

## 奖励审查

原奖励：严格/有界/解释转交 credit 为 1/.6/.5，成功的预算耗尽最多 .4；每调用扣 .02，超专家调用数再扣 .02，错误提交与错误终结各 .5，健康量受损 .5，循环 .25，无效动作 .05，不必要辅助采集 .1。

- **存在明确的准确性与效率交换。** 若专家参考为 6 次、无其他惩罚，20 步严格解决得 `1-.02*20-.02*14=.32`；6 步有界转交得 `.6-.02*6=.48`。这不必然是错误：不确定时安全转交可能正是目标。但如果本轮目标是提高可解决案例的正确诊断率，就应预先调整这个取舍。
- **成本被两次收费。** 超出专家次数后边际调用成本从 .02 变成 .04。专家失败时其调用次数也不是最优诊断成本；应记录参考是否成功，而不把“比失败专家慢”当可靠 regret。对新协议中的联合/预览动作，必须同步计量内部 WLS/拟合次数和耗时，不能仅算外部工具调用数。
- **惩罚可能重叠。** 错误提交、最终健康组件受损、错误终结可来自同一次错误。保留安全约束，但离线报告每项贡献和同源事件，避免把奖励下降简单归因于诊断准确性。
- **不必要采集按真实 family 定义。** 在 mimic 根上，一次合理的证伪动作可能被记作“无须采集”；应分析证据条件下的信息价值。继续坚持正序 WLS 先形成怀疑、充分怀疑才请求辅助数据，不把三相数据变成默认入口。
- **整条 episode 共用优势。** 好坏路径的共享前缀、确认步骤也被整体奖惩；这使关键目标选择信号稀释。先补语义差异与逐行梯度来源，暂不同时引入未经验证的稠密过程奖励或 target-token mask。

本次提供的唯一奖励对照只改 `call_cost=.01`、`tool_regret_cost=0`，其余 credit 和安全惩罚固定。上述算例变为 `.80` 对 `.54`。这是待验证的偏好设定，不是已证明更优的权重。

## 困难集是否真的能学习

| 子集 | 开发根数 | 记录中的 baseline / ranked ledger | 判断与下一步 |
|---|---:|---:|---|
| 参数误排序 | 9 | 1 / 5 | 有排序改进线索；先检查真实线路是否在该策略当步合法 inventory 中，以及 refit 等证据是否对双方同样可见 |
| 表计+参数误排序 | 8 | 1 / 4 | 同上，另检查先修哪一类错误；整条轨迹的最终审计优先于单次验证 |
| 参数/混合模糊 | 40 | 39 / 40 | 主要可优化调用和误提交，成功率空间小；“ambiguous”不等于困难 |
| 同号双端潮流表计 | 24 | 20 / 20 | 记录中的失败已经选对表计；顺序单表估计受到另一偏置污染。先验证联合动作可达性与恢复精度 |
| 异号双端潮流表计 | 24 | 20 / 20 | 健康节点注入表计修正也会被接受；需区分策略误选、验证器假阳性和现有观测下无法区分的情况 |
| 其余 | 104 | 104 / 104 | 保留为回归与效率对照，不作为主要诊断学习信号来源 |

注意：以上分组和数值只复述已提交记录；“其余”合并 dominant、普通表计、低效应谐波、拓扑与健康根。

训练集 baseline 已达 242/256=94.5%，开发集 185/209=88.5%。开发集更难不能证明训练采样会产生成功差异。训练计划只有 8 个误排序根，均匀抽 64/256 时平均每轮约 2 个；需要在小探针中有意识覆盖这些根，但不把开发失败复制进训练。

**92.3% 不是严格策略上限。** ranked-ledger 的数值使用 screen profile 和 learned ranker；baseline 使用 classifier gate。先匹配观察、合法动作、内部计算预算，再谈 RL 超过“同等条件的专家”。

**126/177 的 separable 标签也不是信息论上限。** `identifiability.py` 只在初始状态测试有限 top-k 和真目标的单候选验证。它合并 ACCEPT_PARTIAL 和 ACCEPT_FINAL；一次真表计通过不代表双表恢复完成。错误候选通过，仍可能被其他可见证据排到真候选之后。本次已修正文档中“所有策略上限”的过强表述，保留旧标签兼容历史结果。

**动作和协议限制已在代码中确认：**

- `providers/matpower.py` 的底层 `correct_measurements` 接受 `suspect_group` 联合求解；但初始 measurement context 主要提供单表，以及有明确物理条件的 Vm 联合组，没有一般双端潮流对动作。应首先查每条失败轨迹的完整合法动作清单。
- 参数处于 ambiguous 模式时候选被限为前 2 条；dominant 模式的 provider 则可提供更长排名。因此不要把旧笔记中的“只给第一条”套到全部最新状态；要按轨迹实际 inventory 计算真目标可达率。
- `state_store.py:rollback` 仅允许 REJECT/INCONCLUSIVE，接受候选不能撤回比较。记录称 14 个开发根、19 个训练根的真候选 ACCEPT_FINAL、错候选仅 ACCEPT_PARTIAL；这是优先做受限只读预览的线索，不等于 14/19 个已证明能恢复的 episode。
- mimic builder 构造 synthetic row 时没有保留 clean row 的 `source_realization_id`。不同 seed/根 ID/注入幅值不能证明底层 operating-window 不重叠；应补 clean-parent lineage 审计。当前完整文件未取得，不能宣称已发现或排除了实际泄漏。

困难集没有覆盖原标准集中的 HIF、measurement+HIF、unbalance 等所有家族；下一轮必须保留原 160 根回归评测。

共同条件：冻结 R2 起点、同一组训练根、同一 seed；固定 GNN、环境、验证器、40 步预算与所有审计门槛。新结果采用独立输出目录；现有 hard_v1 与 hard_r2_baseline 不变。

E1 的 T=1.3 是候选，不是已经选出的最佳温度。若 T=1.0 的精确根/adapter/seed 轨迹已存在就复用；禁止用后续更新后的 adapter 轨迹冒充冻结 R2 探针。

E3/E4 共用 frozen rollout 是一次受控离线重算对照，各自从 R2 起步；这不授权连续复用旧 rollout 更新多个新策略。不要在当前 hard_v1 目录直接改温度、奖励或优势设置后继续。

最终只对筛选胜出的配置运行 3 个独立训练随机种子；保持根案例和评测噪声一致，报告逐根配对 bootstrap 区间/失败转换表，二元成功可补 McNemar 精确检验。209 根是开发集，正式论文结果还需要未参与调参、按物理父场景隔离的测试集。IEEE 57/118 转移应作为后续独立验证，不能从本轮 IEEE 14 推断。

## 本次已实施内容与边界

- 默认拒绝多个无 importance-ratio 的 optimizer steps；原四份配置明确加了历史复现 opt-in，新六份探针/训练配置使用单步。
- 采样概率进入 TrainingRow，可在参数更新前检查 teacher-forced logprob；训练保持 gradient checkpointing 所需的 train mode，但禁用 Dropout 模块。真实 Gemma 的 functional dropout、cache/no-cache、4-bit 数值差异仍由真实模型探针检查。
- 阻止训练时再次截短 rollout prompt；严格检查模式拒绝配对、prompt 和概率异常。
- update checkpoint 绑定完整 rows 与 settings 的 SHA-256，防止行数相同但内容/温度变化时错误续训；旧 v2 checkpoint 必须继续使用旧提交，不与新合同混跑。
- 记录最大梯度行的根 ID、sample、step、优势、token 数和裁剪阈值，断点恢复保留这些信息；总梯度非有限拒绝 optimizer step。
- 离线学习信号报告、32 根分层训练探针选择器、split/父场景可用标识检查、严格解决与转交分解指标。
- 不调整候选/事务协议、训练集真值、验证容差或现有 HPC 任务。P1/P2 仍是待运行的研究设计。

本地验证：**91 passed, 1 skipped**；命令和依赖版本见 `research/hpc/rl_review_20261015/README.md`。通过 CPU 单元测试和 tiny PEFT 模型测试只证明相关代码行为；不证明 12B 模型在困难集上获得了更高成功率。
