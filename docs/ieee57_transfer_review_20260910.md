**What is already established locally**

An independent probe loaded installed PYPOWER's `case57()`, solved three uniformly scaled operating conditions, serialized cases to explicit temporary `.m` paths, and ran the repository WLS. It compared admittance-derived telemetry against generator-minus-load injections, solver branch-flow columns and flow-plus-shunt nodal balances. Maximum discrepancy across the successful solves was 8.74e-7 pu. This is an independent arithmetic cross-check, not an independent simulation engine.

**Do not inherit 0.80-1.25 as an established feasible range.** The failure at 1.25 is a solver outcome, not a proof of mathematical infeasibility. Conversely, PF convergence does not demonstrate compliance with voltage, generator or thermal limits. Calibrate acceptance and rejection by operating condition and fault family, and document the case's unvalidated thermal ratings. Do not silently relax limits until the desired number of scenarios is reached.

WLS succeeded on noiseless data from all five successful PF/OPF solves. On the base OPF case, five unfiltered noise draws with sigma(Vm)=0.001 and sigma(power)=0.01 produced J values 376.438, 303.905, 399.812, 384.577 and 394.014, all below 444.889. Recomputing the weighted squared raw residuals reproduced J. Squared normalized-residual sums would incorrectly reject four of those five draws if substituted for J. Five draws are a smoke check, not a false-alarm calibration study.

The research provider already uses branch-row identities for corrections and computes the seven measurement blocks from case dimensions. Preserve its action schema for frozen-policy evaluation. The MCP `correct_topology_from_path` surface is a different implementation: it still builds the IEEE 14 pocket node-breaker model ([MCP topology](../mcp_server/matpower_server.py#L1263)). Passing `case57` to that surface does not establish IEEE 57 support.

**Balanced-only evaluation can preserve the telemetry acquisition protocol.** Existing unavailable-telemetry responses identify channels as unavailable and cause status as unknown; a bound acquisition attempt can clear acquisition prerequisites without executing HSE/OpenDSS. Preserve those responses and report acquisition/tool availability. Do not fabricate negative harmonic or three-phase measurements to unlock corrections. Keep WLS, required requests and correction verification in their existing order. This is a compatibility route for a balanced-only testbed, not evidence that those unavailable disturbances have been ruled out physically.

Use the strict research environment (`production_dataset_mode=True`) and omit waveform payloads, HIF windows, stored NLM results and waveform-family signatures from balanced roots. Genuine IEEE 57 parameter scans are still required. The [unavailable response paths](../psse_env/providers/matpower.py#L2971) and [same-state acquisition gates](../psse_env/actions.py#L210) support this route. Three existing provider/environment tests passed in 0.607 s during this review: diagnostics without runtime data fail closed, diagnostics are blocked on an unverified candidate, and the production WLS/context/correct/verify cycle works. Those tests use the existing IEEE 14 fixture; they do not validate IEEE 57 fault recovery.

Three-phase work requires stronger mismatch checks than the supplied review lists. [Branch-current localization](../three_phase_nlm/branch_current_analysis.py#L202) defaults to IEEE 14 line parameters and can skip unknown rows. [HIF model resolution](../three_phase_nlm/hif_parameter_estimator.py#L70) can fall back to the IEEE 14 OpenDSS model. Disable these fallbacks for a non-IEEE14 system before enabling extended telemetry. Then validate the generated three-phase model against the canonical balanced solution. Positive- and zero-sequence line parameters are distinct inputs in [OpenDSS line models](https://dss-extensions.org/dss-format/Line.html); the missing voltage/sequence/grounding assumptions must be explicit.

**Experimental safeguards to carry into implementation**

The September 9 staged workflow evaluates through [scripts/run_dagger_research.py](../scripts/run_dagger_research.py#L1213), with physical-root isolation. The shorter legacy [research.run_dagger aggregation](../research/run_dagger.py#L135) groups by scenario/episode aliases instead. Reuse the current staged workflow and its auditing; do not assume all research launchers enforce identical splits. The current training stage already supports [continuing the previous adapter](../research/hpc/full_pipeline_20260907/stage_train.sbatch#L68).

Add a parent operating-realization/window ID for split assignment **before** generating scans, noise variants, overlays or permutations. Keep the existing [exact physical fingerprint](../psse_env/dagger/splits.py#L184), which includes the actual telemetry and error realization. Different derivatives can legitimately have different exact hashes while still sharing a split parent. Count physical roots separately from episodes and report both exact-root and parent-lineage counts.

The existing [September 9 report](../docs/ten_sigma_rerun_20260909.md#L29) records R1 146/160, R2 147/160 and expert 147/160 on development data. That supports testing transfer next, but R2 also records 11 false commits versus the expert's zero in the same summary table. Task-success parity does not establish equal intervention behavior. Retain direct final-state auditing and healthy-component checks; a lower residual or a `resolved` token alone does not prove recovery.

Preserve the ten-sigma **minimum** regime for the first comparison, record actual sigma multiples, and distinguish a fixed meter count from a fixed meter fraction. Keep teacher-admission statistics separate from evaluation outcomes. DAgger adaptation should retain audited expert targets on learner-visited states; learner action execution, beta mixing and label retention are separate decisions. The repository's selective truth-audited variant should not inherit unqualified guarantees from [the original DAgger analysis](https://proceedings.mlr.press/v15/ross11a.html).

The next implementation milestone is shared balanced case support plus an audited IEEE 57 development testbed. Fresh clean WLS feasibility is demonstrated here. IEEE 57 fault recovery, teacher quality, zero-shot policy performance, statistical calibration and adaptation remain to be measured.
